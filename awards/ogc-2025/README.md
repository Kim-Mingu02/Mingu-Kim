## 1. 문제 정의

이 문제는 여러 항구를 순차적으로 방문하는 선박에서 차량 수요를 어느 위치에 싣고, 언제 내리고, 필요할 때 어떻게 재배치할지를 결정하는 문제이다.

수요 `K`는 출발 항구 `O`와 도착 항구 `D`를 가지는 차량 수요를 의미한다. 구현 코드 기준으로는 하나의 수요가 `((O, D), quantity)` 형태로 주어지며, 알고리즘은 각 수요 인덱스 `k`에 해당하는 차량들을 선박 내부 노드에 배치한다.

```text
K = ((Origin Port, Destination Port), Quantity)
  = ((O, D), r)
```

선박 내부는 그래프(graph)로 표현된다.

```text
Node 0        : Gate, 차량 출입구
Hold nodes    : 차량을 배치할 수 있는 공간
Ramp nodes    : 층과 층을 연결하는 램프
Edges         : 차량이 이동할 수 있는 연결 경로
```

목표는 단순히 모든 차량을 싣고 내리는 것이 아니라, 하역 시 불필요한 재배치(rehandling)와 임시 하역 후 재적재 비용을 줄이는 것이다.

---

## 2. 기존 FIFO/LIFO 전략의 한계

초기 접근은 FIFO(First-In First-Out) 또는 LIFO(Last-In First-Out) 관점에서 생각할 수 있다. 그러나 복잡한 OD 수요가 동시에 존재하는 선박 적재 문제에서는 FIFO/LIFO만으로 좋은 배치를 만들기 어렵다.

### FIFO/LIFO가 부족한 이유

| 한계 | 설명 |
|---|---|
| OD 조합을 충분히 반영하지 못함 | 단순 적재 순서만 보면 같은 도착지 차량을 묶거나 먼 도착지 차량을 안쪽에 배치하는 전략이 약해진다. |
| 통로 차단 위험을 사전에 반영하기 어려움 | 어떤 노드에 차량을 놓으면 뒤쪽 공간 전체가 막힐 수 있는데, 단순 FIFO/LIFO는 이 영향을 직접 평가하지 않는다. |
| 선박이 가득 차는 시점의 병목을 예측하지 못함 | 만재 시점 이후 하역해야 할 차량이 출입구와 멀어지면 재배치 비용이 크게 증가한다. |
| 재배치 의사결정이 단순해짐 | 막힌 차량을 어디로 옮길지, 임시 하역이 나은지, 선내 재배치가 나은지를 상황별로 비교하기 어렵다. |

따라서 본 알고리즘은 단순 순서 규칙 대신, 각 후보 위치를 점수화하는 휴리스틱(heuristic scoring) 방식으로 발전시켰다.

---

## 3. 핵심 아이디어 요약

본 알고리즘의 핵심은 다음 네 가지이다.

```text
1. 같은 도착지 차량은 서로 가깝게 배치한다.
2. 더 늦게 내리는 차량은 더 안쪽 또는 더 먼 공간에 배치한다.
3. 게이트와 램프를 잇는 메인 통로는 최대한 늦게 사용한다.
4. 선박이 가득 차는 병목 시점 이전에 중요한 수요의 자리를 미리 예약한다.
```

이를 통해 같은 도착지 클러스터링(clustering), 먼 목적지 수요의 깊은 배치, 통로 보존, 병목 시점 대응을 동시에 수행한다.

---

## 4. 선박 내부 그래프와 메인 통로 관리

선박 내부에는 게이트(gate), 보관 공간(hold), 램프(ramp)가 존재한다. 차량 이동은 이 노드들을 연결하는 그래프 위의 경로로 표현된다.

특히 게이트와 층간 램프를 잇는 경로는 전체 하역 가능성을 좌우하는 핵심 통로(passageway)이다. 이 통로에 차량을 너무 일찍 배치하면 뒤쪽 공간이 남아 있어도 접근할 수 없게 된다.

따라서 알고리즘은 다음 방식으로 메인 통로를 보호한다.

```text
Gate
  ↓
Main passageway
  ↓
Ramp nodes
  ↓
Upper/lower floor spaces
```

### 메인 통로 처리 방식

| 단계 | 처리 내용 |
|---|---|
| 1 | 게이트와 램프, 층간 이동에 중요한 노드들을 passageway 후보로 식별한다. |
| 2 | 해당 노드들은 일반 배치 후보보다 낮은 우선순위를 갖도록 penalty를 부여한다. |
| 3 | 적재 가능한 다른 공간이 남아 있는 동안에는 통로 노드 사용을 피한다. |
| 4 | 통로 노드에 화물이 배치되기 시작하는 시점을 병목 위험 신호로 본다. |

개념적으로는 게이트와 램프 노드를 MST(Minimum Spanning Tree) 방식의 최소 연결 통로로 묶어 주 통로를 확보하는 전략이다. 구현에서는 `passageway_nodes`를 별도 집합으로 구성하고, 해당 노드에 배치할 경우 `passageway_penalty`를 적용하는 방식으로 반영하였다.

## 5. Reward / Penalty 기반 위치 평가

각 차량을 적재할 때, 알고리즘은 현재 이동 가능한 후보 노드들을 평가한다. 후보 노드마다 reward와 penalty를 계산하고, 가장 높은 점수를 가진 위치를 선택한다.

### 위치 평가의 기본 구조

```text
Score(candidate node, demand k)
  = 같은 도착지 인접 reward
  + 더 먼 도착지 인접 reward
  + 깊은 위치 reward
  - 통로 점유 penalty
  - 차단 공간 penalty
  - OD conflict penalty
```

### 주요 평가 기준

| 평가 항목 | 의도 |
|---|---|
| 같은 도착항구 `D`를 가진 수요와 인접 | 같은 시점에 하역할 차량들이 모이도록 유도한다. |
| 나보다 더 늦게 하역하는 수요와 인접 | 늦게 내리는 차량이 더 안쪽에 남고, 빨리 내릴 차량이 상대적으로 접근 가능한 구조가 되도록 유도한다. |
| 게이트에서 먼 위치 | 장기 체류 차량을 선박 깊은 곳에 배치하여 출입구 주변을 보존한다. |
| passageway 노드 | 메인 통로를 막지 않도록 penalty를 부여한다. |
| 배치 후 접근 불가능해지는 빈 공간 | 강한 penalty를 부여하여 dead space를 줄인다. |
| 복잡한 OD 충돌 구조 | 재배치 위험이 높은 조합에는 conflict penalty를 적용한다. |

---

## 6. 같은 도착지 클러스터링

같은 도착항구를 가진 차량은 비슷한 시점에 하역된다. 따라서 이 차량들이 흩어져 있으면 하역 시 여러 위치에서 접근 경로를 확보해야 하고, 재배치가 증가할 가능성이 커진다.

본 알고리즘은 같은 `D`를 가진 차량이 서로 붙어 있으면 reward를 부여한다.

```text
if candidate_demand.destination == neighbor_demand.destination:
    score += same_dest_reward
```

효과는 다음과 같다.

```text
Before
D=5 차량이 여러 층과 여러 구역에 흩어짐
→ 하역 시 여러 경로를 열어야 함
→ rehandling 증가

After
D=5 차량이 하나의 군집으로 형성됨
→ 하역 시 한 영역을 집중적으로 처리
→ rehandling 감소
```

## 7. 먼 목적지 수요를 안쪽에 배치

하역 시점이 늦은 차량은 선박 내부에 오래 머문다. 이 차량들이 출입구 가까이에 있으면 이후 항구에서 빨리 내려야 하는 차량의 통로를 막을 수 있다.

따라서 알고리즘은 다음 구조를 유도한다.

```text
Gate 가까움
  → 병목 시점 이후에 내려야 하는 중요 수요
  → 상대적으로 빨리 내릴 수요
  → 단기 체류 수요
  → 장기 체류 수요
선박 안쪽 / 먼 공간
```

일반적인 경우에는 먼 도착지 수요가 더 깊은 공간에 배치되도록 유도하고, 병목 시점에는 예외적으로 병목 이후 하역할 중요 수요가 출입구 근처에 자리를 확보하도록 한다. 이 차이가 본 알고리즘의 핵심이다.

---

## 8. 차단 공간 penalty

어떤 노드에 차량을 배치하면 그 뒤쪽 빈 공간이 더 이상 게이트에서 접근 불가능해질 수 있다. 이 경우 선박에 실제 빈 공간이 있어도 사용할 수 없는 공간(dead space)이 생긴다.

알고리즘은 후보 노드에 차량을 가상 배치한 뒤, BFS(Breadth-First Search)로 접근 가능한 빈 노드를 다시 계산한다.

```text
1. candidate node에 차량을 임시 배치
2. gate에서 BFS 수행
3. 기존에는 접근 가능했지만, 배치 후 접근 불가능해진 빈 노드 수 계산
4. blocked_count가 클수록 강한 penalty 적용
```

개념식은 다음과 같다.

```text
score -= blocked_empty_nodes * blocked_penalty_factor
```

이 로직의 목적은 단순히 현재 차량 하나를 좋은 위치에 두는 것이 아니라, 이후 적재와 하역에 사용할 수 있는 공간의 연결성을 보존하는 것이다.

---

## 9. 지능형 선내 재배치

하역해야 할 차량 앞에 다른 차량이 막고 있으면 재배치가 필요하다. 이때 무조건 임시 하역을 수행하면 비용이 커질 수 있다.

본 알고리즘은 두 가지 선택지를 비교한다.

| 선택지 | 설명 |
|---|---|
| 선내 재배치(relocation) | 막고 있는 차량을 선박 내부의 다른 빈 노드로 옮긴다. |
| 임시 하역 후 재적재(temporary unloading & reloading) | 차량을 게이트 밖으로 임시 하역한 뒤 다시 싣는다. |

비교 기준은 이동 경로 비용이다.

```text
relocation_cost = F + relocation_path_length
temporary_cost  = temporary_unload_cost + reload_cost

if relocation_cost < temporary_cost:
    선내 재배치 선택
else:
    임시 하역 후 재적재 선택
```

재배치 위치를 고를 때도 같은 도착지 reward, 통로 penalty, 차단 공간 penalty를 사용한다. 따라서 재배치가 단순 임시 이동이 아니라 이후 하역 구조까지 고려하는 의사결정이 된다.

---

## 10. 병목 항구 분석

수요를 분석하면 재배치 비용이 가장 많이 발생하는 시점은 대체로 선박이 가득 차는 항구이다. 이 시점에는 빈 공간이 부족하고, 메인 통로까지 화물 배치 후보가 되기 시작한다.

본 알고리즘은 이 시점을 병목 항구(bottleneck port) 또는 peak port로 본다.

```text
onboard demand at port p > effective hold capacity
→ p를 병목 위험 항구로 판단
```

여기서 effective hold capacity는 전체 hold 공간에서 passageway로 보호해야 하는 노드들을 제외한 실질 적재 가능 공간으로 볼 수 있다.

핵심 인식은 다음과 같다.

```text
게이트 가까이에 있어야 하는 수요는 단순히 빨리 내리는 수요가 아니다.
선박이 가득 차는 시점 이후에도 남아 있어야 하거나,
그 시점에 하역해야 하는 수요가 오히려 게이트 근처 접근성을 확보해야 한다.
```

즉, 하역 순서만 보는 것이 아니라 `선박이 가득 차는 시점`을 기준으로 자리를 선점해야 한다.

---

## 11. 병목 이전 자리 예약 전략

메인 통로에 화물이 배치되는 시점부터 병목이 발생한다고 보고, 알고리즘은 병목 시점에 하역해야 하는 수요를 미리 파악한다. 그리고 병목 이전 항구에서 해당 수요가 사용할 자리를 예약(reservation)한다.

### 예약 전략의 단계

```text
Step 1. 각 항구별 선내 잔류 수요량을 계산한다.
Step 2. effective hold capacity를 초과하는 첫 병목 항구를 찾는다.
Step 3. 병목 항구 전후에 중요한 수요를 phase-1 대상 수요로 분류한다.
Step 4. 해당 수요가 들어갈 위치를 미리 예약한다.
Step 5. 예약 위치에는 조건을 만족하는 수요만 임시로 들어갈 수 있다.
Step 6. 예약 대상 수요가 도착하면 해당 위치에 우선 배치한다.
```

### 예약 위치 사용 규칙

예약 자리는 완전히 비워두는 것만을 의미하지 않는다. 예약 대상 수요가 아직 출발하지 않았다면, 그 전에 하역될 수요만 임시로 해당 위치를 사용할 수 있다.

```text
예약 대상 수요가 아직 배치되지 않은 경우:
    병목 전에 하역 완료되는 수요만 임시 배치 허용

예약 대상 수요가 도착한 경우:
    예약된 위치에 우선 배치
```

이 방식은 단순히 빈 공간을 아끼는 것이 아니라, 병목 시점 이후의 접근성을 미리 설계하는 방법이다.

|---|---|
| 같은 도착지 클러스터링 | 같은 항구에서 내릴 차량들이 가까운 위치에 모인다. |
| 장기 체류 수요의 깊은 배치 | 늦게 내릴 차량이 출입구 주변을 점유하는 현상을 줄인다. |
| 메인 통로 보존 | 게이트와 램프를 잇는 통로를 후순위로 사용하여 접근성을 유지한다. |
| dead space 감소 | 빈 공간이 존재하지만 접근하지 못하는 상황을 줄인다. |
| 재배치 비용 감소 | relocation과 temporary unloading을 비용 기준으로 비교한다. |
| 병목 시점 대응 | 만재 시점 이후의 하역 가능성을 고려하여 사전에 자리를 예약한다. |

---

## 16. 정리

본 알고리즘은 FIFO/LIFO 같은 단순 순서 기반 전략에서 출발했지만, 복잡한 OD 수요와 다층 선박 그래프에서는 단순 규칙만으로 재배치 비용을 줄이기 어렵다고 판단하였다.

따라서 각 배치 후보를 reward와 penalty로 평가하는 휴리스틱을 설계하였다.
같은 도착지 수요를 클러스터링하고, 먼 목적지 수요를 깊은 공간에 배치하며, 메인 통로를 후순위로 사용하고, 병목 항구 이전에 중요한 수요의 위치를 예약하는 방식으로 전체 비용을 낮추고자 하였다.
